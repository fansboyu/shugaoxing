# 客户服务器接入说明

模板在总控导入。客户服务器只接收完整静态发布版本，不需要克隆官网 GitHub、安装文章数据库/Redis、配置 OSS AccessKey。

## 首次接入（一台服务器一次）

1. 先备份、检查现有业务及 80/443 占用。当前 Agent 管理专用 Caddy 的整份配置，
   不可直接接管带有其他业务路由的 Caddy；否则手工路由可能被覆盖。
2. 安装匹配主控版本的 Node.js（项目要求 >=24）、Agent 代码及依赖、Caddy。
   不是复制单个 agent.mjs 即可运行。建立最小权限运行账号。
3. 参考主控仓库 deploy/site-agent.service；核对 ExecStart 的 Node 实际路径，
   不要假设总是 /usr/bin/node。Agent 数据目录 /var/lib/site-agent 可写、Caddy 可读。
4. Caddy 管理端口仅 127.0.0.1:2019，Agent 健康端口仅 127.0.0.1:4322。
   Caddy 用 run --resume 恢复最后有效配置，持久化自动保存配置和证书。
5. 主控注册服务器，取得独立 Agent token，写入受保护的 /etc/site-agent/agent.json。
   control=https://admin.shugaoxing.com，mode=production，root=/var/lib/site-agent，
   caddyAdmin=http://127.0.0.1:2019。token 不入 Git、不使用主控管理员密码。
6. 启动 Caddy / Agent，设置开机启动，确认主控显示在线。

## 每新增一个网站

1. 主控创建网站，确认电话、域名、备案，绑定模板和目标服务器。
2. 客户域名 A 指向该服务器公网 IP；如存在 AAAA，确保 IPv6 到达正确服务器。
   当前每站单域名，根域和 www 不会自动同时获得别名配置。
3. 公网允许 TCP 80/443，SSH 限可信地址；不要公开数据库、Redis、2019、4322。
   HTTP/3 按需开放 UDP 443。出站能访问总控、OSS、证书机构和 DNS。
4. 总控发布，Agent 主动领取任务并校验包，自动管理域名路由与 HTTPS。
   不必逐站手工编辑 Caddyfile，也不必给每个站点安装一个 Agent。
5. 验证 HTTPS、首页、列表、详情、电话、备案、OSS 图片及回滚。

站点目录：/var/lib/site-agent/sites/<site-id>/releases/<release-id>/。
当前无自动清理保证，需监控磁盘、制定版本保留策略，禁止删除当前服务版本。
备份 Agent 状态和 Caddy 配置/证书。总控断线不影响已部署静态站访问。

本次只改模板，未登录或修改客户服务器，不能据此认为客户 Agent 已部署完成。
